# 0.5.1 与 X 使用规范的符合性报告

核查日期：2026-10-21。范围：当前插件的平台规范风险，不判断各地区法律；平台违约与法律违法不是同一问题。

## 综合判断

**当前版本不能认定符合 X 使用规范，平台合规风险为高。** 问题主要在内部响应采集、脚本操作网页的技术路径；人工逐次确认、无后端和本地存储是有效约束，但不是官方许可。[服务条款 §4](https://x.com/en/tos)、[自动化规则](https://help.x.com/en/rules-and-policies/x-automation)

“高”表示实现与明确限制直接相关，建议推广前处理；不是封号概率，也不表示 X 已对本插件作出违规认定。未找到针对“只读取已经加载的响应”的明确豁免。

**独立手动点赞的行为设计有官方支持，但当前实现仍有接入风险。** 官方允许用户在第三方应用逐次点击点赞，同时要求官方 API，禁止浏览器自动化；两项需要一起满足。[开发者指南：Engagement、Official API Only](https://docs.x.com/developer-guidelines)

## 实现事实

以下为代码核对结果，不是官方对本项目的判断：

- [observe.js](../../extension/observe.js)、[manifest.json](../../extension/manifest.json)：MAIN world 包装 `fetch/XHR`，读取同源白名单通知及网页 `/i/api/graphql/…` 响应；无独立主动补抓历史、无主动读取 Cookie/私信，未实现官方开发者 OAuth/API 接入；本次未见 X 对该方案的单独书面许可。
- [continuous.js](../../extension/continuous.js)：用户每次点击点赞后调用背景原生 `like/unlike.click()`；每次点击发送后调用原生发送，保存成功才自动开下一条；跳过自动关闭并按需保存草稿。发送、跳过不点赞。
- [core.js](../../extension/core.js)、[background.js](../../extension/background.js)：本地存 ID、handle、关系、互动及最多 200 字片段；无项目后端。每类最多 10,000 条，90 天按最近观察时间；清理仅在写入执行，重复观察会续期，**不是后台到期即删**。
- 无独立清空按钮或远端删除/转私密同步；未存 protected 状态；多账号共享缓存，统计按 actor 区分。XReply 为其他扩展，本插件不生成 AI 内容。

## 官方原文与适用判断

### 访问与网页脚本

现行[服务条款](https://x.com/en/tos)生效于 **2026-10-09**，§4 禁非已发布接口访问，并有短引：

> “crawling or scraping the Services in any form, for any purpose without our prior written consent is expressly prohibited”

同节限制分发协助违规的产品。免费、开源、本地存储没有明确豁免。

[自动化规则](https://help.x.com/en/rules-and-policies/x-automation)更新于 **2026-04**，明确禁止：

> “Use non-API-based forms of automation, such as scripting the X website.”

**本项目推断：** 被动观察不同于大量主动爬取，但仍提取并保存内部响应；代理按钮及自动打开下一条与网页脚本限制直接相关，风险高。不能仅因地址有 `api` 就称官方授权 API，也不能断言 X 已针对这种被动观察作出个案裁定。

### 手动点赞、回复与真实性

[开发者指南](https://docs.x.com/developer-guidelines)的允许示例是：

> “Third-party app lets user tap a like button on a post”

它同时排除非官方网页自动化。用户逐次主动点击不等于无人自动点赞；不能仅凭 `.click()` 判定确定违规，但当前代理路径未有明确许可，解释和授权风险仍在。因此“手动比自动批量风险低”仅指行为维度。

[自动化规则](https://help.x.com/en/rules-and-policies/x-automation)禁止自动点赞；自动回复另有对方先表达接收意愿、退出等条件，AI 回复机器人需要事先书面批准。当前逐条人工确认不应直接等同无人值守机器人；推荐帖出现在主页也不等于作者同意接收自动营销。

[真实性政策](https://help.x.com/en/rules-and-policies/authenticity)限制高量、重复、无关且干扰体验的回复及互换互动。**推断：** 私人往来计数不直接构成操纵；若宣传成互评涨粉或引导模板评论，会增加风险。不存在本次已核实的“每分钟几条保证安全”阈值。

### 开发者条款、缓存和删除

[开发者协议](https://docs.x.com/developer-terms/agreement)更新于 **2026-04-27**，其 API 定义指开发者站点提供的能力；访问 Licensed Material 等也涉及协议接受。未 OAuth 不能武断推导为所有开发者要求均不适用；同样不能假装当前已取得该许可。通用条款/行为规则是直接基础，开发者条款是潜在关联约束及官方 API 路线的明确要求。

[开发者政策](https://docs.x.com/developer-terms/policy)涉及 interception、隐私告知、保护/屏蔽状态及离线内容更新。内容变化应尽快处理，收到 X/相关账号所有者请求后须在 24 小时内处理；[指南](https://docs.x.com/developer-guidelines)还对删除/停用内容列出 24 小时要求。**这不是要求每篇帖子每 24 小时轮询。**

**本项目缺口：** TTL 不能替代删除同步，200 字仍是内容副本；账号共享缓存未证明始终满足保护状态边界，也没有证据证明已发生越权披露。README 已有隐私说明和 Issues 联系入口；官方不要求名为 `PRIVACY.md` 的文件，但仍需核对告知完整性、联系及删除请求机制。

## 逐功能风险表

风险是对当前实现的判断，不是处罚预测；依据为上文政策和代码事实。

| 功能 | 判断 | 关键原因 |
| --- | --- | --- |
| 观察内部响应 | **高** | 被动读取不是明确豁免；授权和 interception 问题 |
| 原帖/已回/已点赞标签 | 显示本身较低，数据路径高 | UI 用途不能豁免底层采集 |
| 我评他/他评我、NEW | 显示本身较低，用途升级需复核 | 私人往来计数不直接构成操纵；底层数据路径仍有风险 |
| 本地关系、正文片段 | **中至高** | 无后端减少暴露，但删除和保护状态有缺口 |
| 独立手动红心 | 行为可接受，技术路径高 | 一次一帖；仍代理网页按钮 |
| 发送并下一条 | **高** | 人工确认是缓解；网页脚本流程仍存在 |
| 跳过/自动存草稿 | **中至高** | 无公开互动，但非自动化限制的明确例外 |
| 免费开源/推广 | 不能消除风险 | 不等于 X 授权；勿随代码公开个人缓存 |
| 与 XReply 组合 | 需评估实际组合行为 | 本插件不生成 AI，勿直接认定 AI bot |

## 建议优先级

**P0：对外准确披露。** 不承诺完全合规/不封号，说明非 X 官方、未获认可；定位个人记忆辅助，避免互赞互评、养号涨粉宣传。维持逐条人工确认；不要通过随机延迟、模拟真人或绕过检测替代合规。

**P1：缩小当前缺口。** 提供清空及按账号删除，减少正文缓存；使清理不依赖后续写入，处理远端删除及保护状态。回到用户直接点原生按钮可减少写入自动化风险，但保留响应观察仍不能宣布整体合规；仅存 ID 也不是自动豁免。

**P2：可持续公开推广应取得 X 对完整方案的书面许可，或迁移官方 API。** 申请应披露采集、缓存、互动流程和期限，不能仅写“UI 优化”。

- [OAuth 2.0 + PKCE](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)：按需授权读帖、发帖、点赞；公共浏览器客户端不能安全保管 client secret。
- [Create Posts](https://docs.x.com/x-api/posts/create-post)：官方 `POST /2/tweets` 发布回复，替代代理网页发送。
- [Like Post](https://docs.x.com/x-api/users/like-post)：官方 `POST /2/users/{id}/likes` 执行用户逐次选择，不代表允许自动点赞。

官方 API **未被本次证明能完整复刻“为你推荐”、网页全部通知及历史**；需核对权限、速率、费用和数据合规支持。缺少等价入口应降级为未知，不能回退未授权采集。OAuth、付费、免责声明都不能豁免平台行为规则。

## 来源与结论边界

以上均为 2026-10-21 访问的 X 官方原始资料。风险评级、代码映射和建议是本报告分析，非 X 认证。**当前答案是“不能认定符合，存在明显高风险点”，而不是“必封号”或“已被认定违法”。** 本报告未改功能，也未取得个案审核；推广或改变自动化程度前应重新核查。
