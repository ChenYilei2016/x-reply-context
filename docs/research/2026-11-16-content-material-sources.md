# 创作工作台：自动素材来源与落地范围

调研日期：2026-11-16，Asia/Singapore。用途：先对齐需求，不是实施方案批准。本轮只查一手资料、公开代码，并对 4 个无凭证读取地址各做一次小规模请求；没有部署、改插件、获取用户凭证或发布内容。

## 结论

可以实现“打开就有素材可选”，不必先让用户手工收集。建议第一版优先做 **自动新闻素材流 → 选一篇或多篇 → 获取可用正文 → 按个人风格改写或合并 → 编辑草稿**；在这条链上加入基于已取素材的轻量角度建议。X 爆文作为可选付费数据源接入，不把它混同于新闻热榜，也不让 X 来源暂缺阻塞整体交付。

对用户的 AI、程序员、数码和娱乐兴趣，先把高相关来源和可加工正文做好，比无差别聚合数千条热榜更节省人工时间。新闻卡片必须区分“只有标题”“已有摘要”“已有正文”，不能把标题交给 AI 扩写成未经来源支持的新闻。

## BlueV 能参考到什么

- 官网称其对优质账号分级监控、按爆发速度排列爆文；公开帮助将插件的流速定义为“发布以来平均每小时浏览量”，不是最近一小时的实际增量。网站爆发指数的完整公式和上游供应商没有被确认。[官网](https://bluev.fun/) · [流速帮助](https://bluev.fun/help#ext-velocity)
- 本轮主 agent 的登录页面实测：角度任务返回 13 个角度，页面标注输入证据为爆文库 40 条、近 7 天点赞大于 10 的 X 帖子 51 条；已有角度附参考原帖，新候选只表示本次结果没发现。该来源数量是网站显示的声明，不等于我们独立验证了它的底层查询。[找角度](https://bluev.fun/angles)
- 可借鉴其“监控来源 → 筛选 → 相关内容检索 → 角度归纳 → 生成”的流程。目前没有取得公开供第三方接入的 BlueV API 证据，不将登录后可见页面或未公开接口假设为长期素材服务。

## X 爆文的两种接入成本

主 agent 核对的供应商公开资料如下，均未用付费凭证实测。

| 方案 | 数据能力和计费 | 取舍 |
| --- | --- | --- |
| X 官方 API | recent search 覆盖近 7 天，最高 100 条／页；当前 Post Read 为每个计费资源 $0.005，同 UTC 日重复资源按定价规则去重 | 官方渠道；广泛扫帖和跨日复查需要预算控制 |
| TwitterAPI.io | 高级搜索返回正文、作者、浏览／点赞等字段；公开价格为每 1000 条返回推文 $0.15，每请求最低 $0.00015。读接口使用服务商 API Key | 单价更低，适合候选；第三方覆盖率、时效和字段可靠性仍需小样本验证，不能视为与官方等价 |

仅举例：每天返回／计费 500 条、30 天，第三方约 $2.25；按官方 500 个计费帖子／天约 $75。此计算不是套餐报价，不含模型、其他资源、空请求最低费用、后续复查或增量读取。[X 定价](https://docs.x.com/x-api/getting-started/pricing) · [X recent search](https://docs.x.com/x-api/posts/search/introduction) · [TwitterAPI.io 定价](https://twitterapi.io/pricing) · [高级搜索返回字段](https://docs.twitterapi.io/api-reference/endpoint/tweet_advanced_search)

可参考 BlueV 的精选账号与主题策略：少量相关作者加主题检索，在预算内取候选，按浏览量、互动和发布时间筛选。若只有一次快照，只能显示累计量或发布以来平均流速；若要“正在加速”，需要多次快照，必须把复查成本算进去。

## 首版建议范围

1. 内置少量相关 RSS 来源，首次打开需要等待拉取，之后开页面先显示上次素材，同时增量刷新；用户无需手工添加或复制素材。展示来源、原发布时间、抓取时间、摘要／正文状态。
2. 默认以相关性、新鲜度筛选；可接热榜显示平台排名。RSS 更新不代表文章已经流行；没有 X 指标就标为新闻素材或热点线索，不虚构“爆文指数”。
3. 点击素材后自动补可访问正文。仅有摘要时明确标注；补取失败保留卡片和原链接，不把空正文当成功。可访问事实足够时再生成。
4. 先实现单篇改写、多篇合并、长文压缩、英文转中文，并提供少量适合用户人设的写法。给出 2～3 个候选，比连续自动生成几十条更便于选用。
5. “找角度”首版基于已检索到的相关文章给出切入点与证据；有 X 来源后再加已有角度归纳、参考原帖和差异角度。统一用“本次素材中未发现”，不保证全网没人写过。
6. 收藏、隐藏、已使用标记和草稿自动保存，避免反复看到同一素材；选中文章的正文和 AI 结果缓存复用。

性能建议是设计边界，不是压测结论：先限制为约 6～10 个源、每源最多 30 条卡片；拉取并发 2～3，使用缓存／退避，按需读取正文，不对整库逐篇调用 AI。纯插件能在浏览器运行时刷新并在打开页面时补拉；电脑关闭时不采集，重开后可以拉取来源届时仍提供的新闻，但不保证补齐已经从 RSS 淘汰的条目。若要求电脑关闭时仍全天收集，才需要服务器定时任务。没有必要为第一版同时部署 TrendRadar、NewsNow 和 RSSHub 三套系统。

内容处理默认保留原始链接与出处，提取事实再加用户观点；不原样复制他人的独创表达或默认复用图片／视频。开放 RSS、开源抓取代码和内容转载授权是三件不同的事。

- 全链路中文成稿质量、发布与排期。此次未生成或发布用户的实际内容。
