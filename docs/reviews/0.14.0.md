# 0.14.0 通知接收过滤、空批暂停与占位收紧

## 范围

点赞原帖、喜欢回复及其多人聚合均在通知响应交给 X 前过滤；关注消息由独立开关控制，两个开关仍默认开启并保留用户关闭选择。评论、转帖、未知类型和未知结构保留。设置变更影响后续响应，关闭后需手动刷新才能重看之前已过滤的消息，扩展不会自动刷新草稿页。

真实 Chrome 导出的已清理响应确认：当前 X 使用 GET `NotificationsTimeline`，入口为 `data.viewer_v2.user_results.result.notification_timeline.timeline.instructions`；点赞事件为 `heart_icon`，关注为 `person_icon`。本地原始诊断产物留在仓库外，未提交账号、正文、请求头或游标数据。

## 实现

- 新模块 `notification-network.js` 处理已核对的通知 GET 响应，覆盖 fetch、XHR 文本及 JSON 读取。识别 AddEntries、ReplaceEntry 与已知 REST 通知引用结构；非通知、POST、未知结构及超出受控规模的响应保持原样。
- fetch 在返回响应前变换，保留响应 URL、状态、头部和克隆行为；XHR 在原生读取属性时提供过滤后的副本。观察记录链路使用原始响应，用户、帖子和互动依据不因显示过滤而丢失。复用 XHR 转发其他操作时移除旧拦截。
- 一批被全部过滤且有底部游标时，保留游标但暂缓下一次原生底部请求；点击「继续加载」只放行一批。如果仍全被过滤，再次停下。顶部增量请求不受底部暂停影响。
- 不主动请求接口、不循环搜索评论。等待队列每个账号/通知分类最多4项，状态分类最多6项，游标记录有界；取消、离页和换账号清理等待项。读取上限8MiB，响应指令与条目数量有界。
- 删除旧点赞/关注 DOM 折叠模块，避免再产生逐条1px占位；「整理列表」仅处理已完成评论。评论卡片及原生 `cellInnerDiv` 的折叠边框、间距一并收紧，保留可测量的亚像素高度以减少累积横线。X 自身已有虚拟高度缓存需刷新页面清除，未直接改写 X 内部状态。
- 空批提示为唯一固定浮层，不追加顶部说明、占位或列表行；回复框打开时隐藏，三个标题栏按钮的位置不变。

## 验证

- 当前51项 Node 测试通过。新增覆盖事件字段、GraphQL/REST、替换项、fetch 克隆读取、XHR 文本/JSON、原始数据保留、空批暂停、一次放行、顶部增量、取消、离页、账号切换和 XHR 复用。旧 DOM 事件折叠及对应测试随替代实现移除；旧版证据保留在历史版本记录中。
- 24项 fetch/XHR 接口入口回归通过，错误记录与关闭空框后误隐藏均为0。
- 仓库外真实响应回放7份：两份完整批次分别过滤7/8条、保留13/12条，顶部及底部游标均保留；空增量返回保持原样。证明字段识别，未将真实数据放入测试夹具。
- 本地浏览器模拟 X：首批1000条点赞/关注在渲染前移除，仅显示2条评论；下一批20条均被过滤时请求数停在2。点击继续后请求数变为3，显示下一条评论。共1020条事件过滤、进入列表的事件为0、隐藏事件占位为0，阅读锚点 top 始终为146.5px，提示节点始终仅1个。见 [数据](network-filter-0.14.0.json) 和 [截图](network-filter-0.14.0.png)。模拟页在未过滤时会实际渲染事件，不会自行忽略它们。

最初验证包含真实响应回放和本地客户端模拟；重载后的真实页面结果补充如下。X 自身的高度缓存仍需刷新页面清除。没有代用户发送、点赞或关注。README、弹窗、安装包及原安装目录同步至0.14.0；本次尚未提交或推送。

## 重载后真实页面补充

点赞/关注聚合通知及事件隐藏占位均为0；页签底部106px，首条可见评论107px，没有顶部累积空白。82条已完成评论折叠行的总高度为0.640625px，三个按钮的坐标及112/80/64px宽度保持不变。数据见 [匿名指标](notification-live-0.14.0.json)，真实账号截图保存在仓库外。

打开/关闭空回复框时控件正确置灰，首次记录到scrollY变化15px，但评论文档坐标没有变化；后续受控复核被浏览器连接切换打断，不能保证所有原生焦点滚动都已消除。真实检查未自然遇到整批过滤场景，空批暂停仍以先前回放/模拟为证。

本轮发现“已完成评论自动整理”在补位数据到达后会再次执行的关联问题，已通过失败测试复现，修正在0.14.1；见该版本记录。
