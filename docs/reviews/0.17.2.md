# 0.17.2 · 搜索结果连续回复

## 原因与修复

原 `entryFeed` 只接受通知、首页和个人主页，搜索结果的小评论按钮虽然能打开 X 原生回复框，却不会建立插件会话。数据观察器原本已包含 `SearchTimeline`，本次不修改接口观察、存储结构或请求行为。

新增搜索「热门／最新」入口，复用现有回复工具栏和成功回执链路。会话以搜索 URL 的查询词、筛选及页签参数识别；参数排序标准化并忽略 `src` 追踪来源。进入 `/compose/post` 后仍核对背景搜索页签的链接，切换搜索词／筛选／页签会停止旧会话。仅处理已加载原生帖子卡片，不主动加载下一页。搜索「用户／媒体／列表」及帖子详情页未新增支持。

新增检查只读取少量搜索页签，不增加整页观察器或持久缓存；无 CSS 修改、不向搜索列表插入标签行。原快捷键、AI、草稿保护、伴随主页及互动计数保持原实现。

## 验证

- 只读查看用户真实搜索页，确认热门与最新分别为 `/search?q=…&src=typed_query` 和带 `f=live` 的原生链接。
- 修复前本地夹具能复现“原生回复框打开，插件工具栏不出现”；修复后 Chrome 搜索夹具 **9/9** 通过。
- 覆盖：热门与最新入口；完整工具栏；跳过保存草稿；本地模拟成功回执入库一次并按原帖计数；排除自己与已回帖子；切页签、改搜索词停止旧会话；来源追踪与参数顺序变化不误停；用户搜索不误启动。
- 输入 100 次未扫描整页帖子，背景卡片位置和高度保持不变。

- 发送和回执来自本地模拟；本轮未在真实 X 发送／点赞或触发 AI。实际已安装版本需重载扩展并刷新 X，真实搜索回复框尚未验收。
