# 0.17.0 · 单个伴随主页窗口

## 行为与边界

回复框原「他的主页」位置改为「伴随主页」。普通左键点击创建一个约 800px 宽的 X 原生 popup 窗口，靠当前窗口右边放置，不移动或缩放来源窗口。原生主页沿用已有个人主页回复工具栏。

已有伴随窗口一律只唤起，**不刷新、不导航、不自动换人**；这比先检查草稿再跳转更保守，避免检查完成后用户继续输入造成竞态。若另一个通知对象请求打开，提示先保存并关闭旧窗口。相同窗口内的手动原生导航由用户自行决定，不由插件纠正或回跳。

- 打开请求在后台合并，不占用历史数据保存队列。只保存小型窗口 ID／初始对象引用，不读取或转移编辑内容。
- 引用放在 `chrome.storage.session`，服务工作线程休眠后仍可恢复；窗口关闭后清理。不会后台预取、轮询、重试或主动翻页。
- 引用保存失败时只关闭尚未加载 X 的新空白窗口；已有窗口唤起失败不创建替代窗口。
- 不增加扩展权限；使用 Chrome 原生 windows/tabs 接口，不适配新的 X 内部接口。
- 原生 X 仍可能自行请求数据、图片和视频，不保证只有一批或 5 篇。此前实测单个页面的 Chrome 内存读数约 396MB，属于页面级快照，不是插件增量或长期性能结论。
- 600px 原生 X 会进入整页编辑，不能复用现有弹窗工具栏；800px 已实测出现工具栏。窄屏可能遮挡左侧区域，窗口可以手动移动；不通过压缩左侧来换取空间。
- **重载／更新／停用扩展或重启浏览器前，需保存并关闭伴随窗口。** 这些操作会清除会话引用；本版不扫描全部浏览器窗口来猜测旧窗口归属。
- Ctrl／Command／中键等原生另开链接行为保留，用户主动打开的普通标签不属于单例管理。
- 右侧使用原 AI 设置；开启自动生成时，手动打开原生回复框仍可能触发生成。打开主页本身不点击回复，不生成、不发送、不点赞。

## 验证

### 已完成

- Node **107/107**，其中 7 项新增伴随窗口测试：并发合并、不同目标不导航、工作线程重建恢复、最小化唤起、关闭与失效引用、存储／唤起失败、来源／账号格式／frame／隐身窗口校验。
- Chrome 本地通知受控回归 **6/6**：20 次快速点击只请求一次；多行非空草稿不变；对象与原生编辑器节点不变；背景卡片位置和高度不变；零发送／点赞；再次唤起仍不改变草稿。使用生产回复工具栏和通知流程，窗口打开结果为模拟。
- 前置真实浏览验证：800px 独立普通窗口出现原主页工具栏，重复聚焦同一窗口不导航；来源“正在关注”空草稿及 8 张卡片位置保持。此项不是本版 popup 窗口端到端验证，也不是通知非空草稿验证。
- 源码、安装 ZIP 与原安装目录的 26 个文件逐字节一致。

### 真实通知页补验（2026-10-26 已完成）

用户重载 0.17.0 并刷新后，在通知回复框输入非空草稿。只读取内容作内存比较，证据文件仅保留长度和比较结果，不保存草稿正文。

- 点击「伴随主页」共 3 次，只有 1 个 800px popup；窗口 ID、标签 ID 和右侧页面 DOM 身份保持一致，没有重新导航。
- 左侧非空草稿、回复对象、连续回复进度保持；77 张已挂载通知卡片的帖子标识、位置和高度全部相同。
- 原窗口尺寸和状态没有变化。关闭测试伴随窗口后，该窗口已消失，左侧草稿仍原样保留。
- 本轮没有打开右侧回复框、触发 AI、发送、点赞或编辑用户文字；没有真实发送入库验收，也不把这次短时验证视作长期性能证明。
