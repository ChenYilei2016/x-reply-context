# 0.17.3 · 回复框最底部的双向互动统计

## 行为

通知、首页为你推荐／正在关注、个人主页帖子／回复、搜索热门／最新，以及伴随主页中的已有回复工具栏，底部统一显示「我评他 N」「他评我 M」。通知回复框将原标签行中的双向计数移到底部，不显示两遍；通知列表本身的标签保持不变。

直接消费既有 CLASSIFY 返回的 personStats，按当前回复的帖子作者取数，不拿原帖作者或个人主页主人代替。没有新增 X 请求、后台消息类别、存储字段或计数计算。

口径沿用双方各评论过对方的不同原帖数，同篇多次含楼中楼只算1；点赞、在自己或第三方原帖下回复不计。确认计数0照常显示0；缺失统计、账号未确认或本地读取失败显示待确认，不用0代替未知。

底部预留28px固定高度，统一复用列表的徽标文案。只有两个数字变化时重建这两个徽标；输入刷新不改写相同数字。原帖摘要和伴随主页仍位于其上方。

## 必要关联修复

首次页面账号识别发生在回复框首次读取之后时，会使该读取失效；搜索页若没有其他DOM变更，可能等到再次输入才发起新读取。本轮用运行时回归复现（渲染版本0、资料版本1），在账号识别后安排一次已有的合并帧刷新修复。不增加轮询、重复网络请求或新全量扫描。

## 验证

- Node **112/112**，新增首次账号识别后资料刷新回归，修复前失败、修复后通过。
- Chrome本地通知和搜索回复框各 **8/8**：底部占位、既有正确计数、无重复计数、延迟／缺失／失败时行高稳定、切换作者不沿用旧数字、无发送点赞。
- 两个入口各输入100次：统计行DOM变更0次，整页帖子扫描0次。
- 初次搜索回归曾出现资料未更新超时，关联修复后从新页面打开回归通过。
- 本轮没有操作真实X发送、点赞或AI；真实新版回复框尚未重载验收。
