# 0.17.6 · 先评论，再点赞，再下一条

组合按钮改为「评论点赞下条」，保留原行布局。流程：

1. 人工点击后通过 X 原生回复按钮发送当前草稿。
2. 匹配当前账号、帖子、请求 ID 的成功回执，并等待同一条本地保存 Promise。
3. 等待 300～750ms，再检查当前账号、页面、目标卡片与后续操作是否仍有效。
4. 已点赞且没有待确认操作时跳过；否则点击原帖原生红心，等待本次成功回执及保存。
5. 成功后才进入当前已加载列表的下一条。

## 异常处理

- 评论失败保留草稿；未确认或本地保存失败不点赞、不自动重发。
- 评论已发但点赞失败、保存失败或10秒无回执时，状态保留为“已发送”；只提供手动下一条，绝不重新发送同一评论。
- 原卡片已移出、用户关闭／换对象／换账号／切到后台时停止后续操作。新输入保留；X 成功发送后清空原编辑器不视为新草稿。
- 已经发出的请求无法撤回；晚到的确认仍经原记录链路保存，但不在新对象上续点／续发。
- 独立点赞按钮、原生回复和跳过保持原作用，原生回复不附带点赞或下一条。
- 不新增轮询、历史补抓或 X 接口调用类型，只调整已有人工触发组合操作的顺序。
