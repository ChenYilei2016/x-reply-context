# 整体功能、架构与性能审阅

后续状态：以下四项已在 [0.16.2](0.16.2.md) 修复并增加回归检查。下文保留 0.16.0 审阅时的原始发现与验证边界。

独立子 Agent 只读审阅，基准为 `1b71a07 / 0.16.0`，不混入 0.16.1 手动推荐功能。按单用户、多标签页、每类约 1 万条本地记录评估。覆盖网络观察 → 入库队列 → IndexedDB → 分类缓存 → 过滤／虚拟列表 → 连续回复 → AI 模型队列的主要调用链。

结论：主要模块边界合理，AI 网络等待已与互动记录隔离；仍有两项数据正确性问题和两项性能／规模边界需要单独修复。以下问题没有在本轮改动观察和存储模块，不能视为已解决。

## 优先修复

### 1. 取消后复用 XHR，可能误记旧帖已点赞

位置：`extension/observe.js:260–285`，尤其 `276–282`。

每次 `send()` 新增一个 `once` 的 `load` 监听，取消请求不会触发它，下一次 `open()` 也没有撤销旧监听。基准代码与 EventTarget 受控复现：同一 XHR 先发 `FavoriteTweet(123)` 后取消，再发 `FavoriteTweet(456)` 成功，得到 123、456 两条已点赞记录；123 没有成功。

这会污染标签与隐藏判断。最小修复是在回调中确认 `requestContexts.get(xhr) === context`，并在 `open/loadend` 清理该请求监听。现有测试的 `handlers[name] = fn` 会覆盖监听器，掩盖复用问题；应补一个支持多监听器的取消后复用测试。

**边界：未确认真实 X 当前是否复用这种 XHR。受控复现证明代码路径有错，不证明线上发生频率。**

### 2. 同一响应的部分对象覆盖完整帖子关系

位置：`extension/core.js:98`。

`extract()` 内按 ID 合并使用无条件覆盖。缺少关系的对象经 `cleanTweet` 会得到空字符串，从而覆盖先前的完整字段。受控输入同 ID 的完整回复（conversationId=100、parentId=100、recipientId=1）和只含作者／正文的部分对象，`entries:[partial, full]` 经栈遍历后，三项关系全部变空。后续观察器无法恢复提取阶段已丢失的数据。

这可能导致原帖待确认、漏识别回复或统计不成立。最小修复：同 ID 合并也采用非空字段覆盖，保留已知关系；补一个完整／部分对象重复出现的测试。

**边界：结构级受控复现，尚未采样确认真实 X 当前此排列的频率。**

## 性能与规模

### 3. 一条重复观察仍触发全量关系重建

位置：`extension/core.js:267–277、302–318`；`extension/background.js:41–44、80–94`；`extension/content.js:202–205`（基准行号）。

批次只要包含 user/tweet，即使关系没有变化，也会扫描点赞、重建回复／人物统计、排序保留记录、检查到期并清空分类索引，再广播所有标签页重算。优先队列无法抢占已经运行的同步计算。

使用现有 `tests/diagnostics/performance-fixture.mjs` 满量状态，每次仅重新摄入一个已知 user/tweet，10 次本机 Node 核心计算为 **28.8–41.9ms/批**，尚不包含 IndexedDB、消息往返和各标签页重分类。多标签快速浏览时会产生不必要的排队。

最小方向：区分仅 `seenAt` 刷新和关系字段变化；前者不重建关联统计或全量失效分类缓存，同时保留有界的到期／容量维护。建议独立修复和测量，不引入新框架。

### 4. 单个响应超过 500 条时仍会截断

位置：`extension/core.js:109–111`；现有 `tests/interaction-latency.test.mjs:39` 起。

`extract()` 对 users/tweets/likes 分别 `slice(0,500)`。单响应 600 条合法帖子只得到 500 条，后续分批无法找回尾部。现有“不截断”测试是两个 300 条响应，未覆盖单响应过大。

修复方向：保留解析资源上限，将已解析记录按 500 条输出给现有合批链路，不在出口直接丢弃；加一个单响应 600 条测试。不能简单去掉全部上限。

**边界：没有证据表明常见 X 分页单次超过 500 条，属于规模边界，不是线上已证实漏记。**

## 未发现确证问题的路径与限制

- AI 具有独立队列、3 并发、12 等待、25 秒时限及按 tab/frame/document 绑定的取消机制。
- Key 不通过状态接口返回，配置操作限设置页；模型域名独立授权，拒绝 X 地址及跨域重定向。此次未发现证据充分的密钥泄露或自动发送路径。
- 正常的分页继续只放行一批；虚拟列表有身份复核、固定隐藏决定及全隐藏恢复入口。没有据此认定必然无限分页或空白堆积。
- 审阅读过主要生产模块、相关测试、README、manifest、打包脚本，并做上述受控复现。子 Agent 未运行全量测试、未操作真实 X／模型、未测长期内存曲线。

建议先修 1、2，再单独测量优化 3；4 结合真实响应规模处理。0.16.1 新功能验证见 [手动推荐说明](0.16.1.md)。
