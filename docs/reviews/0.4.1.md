# 0.4.1：互动计数与连续回复审查

审查日期：2026-10-21。基准由用户确认为 **0.3.3 → 0.4.0**。项目尚无 Git 历史，使用保留的安装包做文件差异；修改前源码与 0.4.0 安装包一致。计数核心 `core.js` 和持久化模块 `background.js` 在这两个版本间未改动。

规格依据：按不同原帖数统计「我评他 / 他评我」，同帖多次算 1；状态仍按同一原帖、同一个人判断；连续发送必须确认成功、保存完成后前进，跳过保护草稿。新增要求是「当前页面已加载的都可以下一步，不用考虑顺序」。两路审查独立进行，以下保留各自结论。

## Standards

**[P2，已修复] 同一成功回复重复入库。** 0.4.0 的 `observe.accept` 把回复放入普通 `OBSERVED` 批次，`continuous.receiveReply` 又直接执行一次 `INGEST`。这违背了用户要求的避免重复调用：每条回复会两次重建索引、统计并写整个本地状态。去重键有效，因此它不直接导致多计或少计。

修复后，已校验的成功回复只经现有 `REPLY_RESULT` 传递，由 `content.js` 统一保存；原生回复和连续回复都走这个入口。回执保留响应附带的用户、帖子和已绑定账号的点赞数据。连续流程等待同一次保存 Promise，普通时间线仍走 `OBSERVED`。未引入新后台接口、成功缓存或等待器。

针对修复的独立复核未发现新增规范问题。没有为代码异味进行额外重构。

## Spec

**[P2，已修复] 回复弹窗期间，计数显示会滞后。** 0.4.0 为避免列表跳动，在任何回复弹窗存在时停止全部标签刷新；连续模式成功后立即打开下一框，后台计数增长后，列表可能整轮显示旧值。

最小复现在同一弹窗内新增「评论 Carol 的另一篇原帖」：后台计数递增，标签仍停留旧值；退出后才显示。修复后沿用固定标签槽位，弹窗内仍更新数字和状态，并排除弹窗内部的引用卡片。9 项布局检查通过，相关行高 / 位置变化仍为 0px。

**新增队列要求已实现。** 每次前进时重新查看当前页面已挂载的评论通知，不再取当前条下方的固定序列；以每批 100 条在本地分类，略过本轮已发送 / 已跳过，以及同原帖同人已文字回复的通知。仅点赞的仍是候选。新消息不会打断编辑，下一步时如已加载可进入候选。不主动翻页抓取。原生回复按钮仍只发送本条。

独立复核未发现新增需求偏差。新队列是本次需求变更，不将旧版顺序规则记作历史缺陷。

## 计数口径与证据边界

- 评论同一原帖多次只算 1；评论对方第二、第三篇原帖依次为 2、3。
- 在自己或第三方的原帖下回复这个人，不增加「我评他」；楼中楼以整段对话的原帖作者为准。
- 缺少原帖作者时暂不计，作者信息补齐后补计；统计不是完整历史总数。
- 用户确认同帖与不同帖两种场景都有，但未提供具体真实帖子链接。当前有证据的缺陷是显示滞后，未复现统计核心吞掉不同原帖的记录，不能将本次修复宣称为已验证解决所有真实漏记。
