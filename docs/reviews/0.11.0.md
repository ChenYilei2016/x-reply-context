# 0.11.0 保护阅读区的自动整理与单次点赞通知清理

## 行为

通知标题栏固定显示「隐藏已回且已点」「整理列表」「自动整理」。自动整理默认关闭，选择保存到当前 Chrome；隐藏规则未开启时暂停，原选择保留。

- 有待处理评论且空闲 10 秒后，仅整理视口下方 600px 之外的卡片。当前阅读区及其上方不动。
- 滚动、触摸、点击、键盘和输入重新计时；回复框、后台、离开通知页时暂停，恢复后重新等待。没有可安全处理的卡片就停下，不轮询保护区。
- 查询返回后再次验证活动、账号、滚动和卡片位置；卡片移入阅读区、用户继续操作或切换账号会使过期自动请求失效。手动整理仍能按用户意图一次应用全部已加载评论。
- 新挂载卡片不立即折叠，等待手动或自动空闲周期，防止补位后马上再清理的连锁行为。自动执行两次之间至少间隔 10 秒。

## 点赞通知仅手动清理

「整理列表」额外隐藏点击瞬间已挂载的点赞通知，单次最多 100 条，做完即停。补位或新到的点赞消息保留，必须再次手动点击才清理；自动整理永远不采纳点赞通知。

复用先前识别原生事件图标的方法，额外用账号、稳定 datetime、事件摘要、链接和片段识别节点身份。不通过“喜欢”等文字猜测，避免误隐藏关注或评论。相对时间从 1 分钟变成 2 分钟不会恢复旧项；节点复用为另一通知时同步清除旧标记。没有稳定时间字段的未知结构保留。

仅添加本地显示标记，不删除 X 通知或取消点赞；关闭隐藏规则可恢复。扩展不主动请求接口、不滚动补抓。X 自身可能为补位加载通知，但新到点赞不会被继续隐藏，不形成插件驱动的循环清理。

## 性能

- 只操作 X 当前挂载节点，通知分类每批最多 100 条，点赞清理每次最多 100 条；不将本地 10,000 条历史全部渲染到页面。
- 滚动/输入已有计时器时仅修改时间和修订号，不重复查询账号、遍历历史或重新创建计时器。测试连续 500 次滚动事件未产生额外账号 DOM 查询。
- 自动整理最多一个等待计时器；无差异不启动，仅保护区存在变化时不持续分类，离页或后台清理计时器。没有新网络 API、后台轮询和新的持久化历史索引。
- 后台批量分类将账号、原帖回复和对话点赞查找表在批内复用；按原有首个匹配顺序取证。每批重新构建，避免点赞撤销、数据更新或账号切换沿用旧缓存。
- 红心批量写入按账号复用查找结果，保持存储格式和统计口径。

本机 Node 模拟用户、帖子、回复、红心各 10,000 条，100 条分类三次样本中位数由约 332ms 降到约 6.6ms；500 条红心写入中位数由约 90ms 降到约 49ms。分别见 [分类优化前](performance-before-0.11.0.json)、[写入优化前](performance-ingest-before-0.11.0.json)、[优化后](performance-after-0.11.0.json)。命令：`node tests/diagnostics/classification-performance.mjs`。

这是同机模拟计算时间，不包含 Chrome 通信、存储序列化和 X 自身渲染，不能据此保证所有设备的帧率或未知规模数据都不卡。
