# 0.9.1 标题栏筛选控件稳定性

## 问题与复现

旧版「整理更新 N」仅在当前已挂载通知存在待应用差异时显示。X 虚拟列表滚动会卸载和重新挂载卡片，待应用数量随之变成 0 或恢复，从而反复隐藏、显示按钮，挤动相邻控件并导致误点。统计数量本来就只代表当前已加载的内容，不适合作为会改变标题栏布局的提示。

先运行 `node --test tests/notification-controls.test.mjs`，真实 card-filter 和 notification-filter 在移出卡片后触发失败：`没有待更新项时也不能移除按钮`（expected false，actual true）。修复后同一测试通过。

## 修改

- 标题栏改成一组固定宽高的控件：「隐藏已回且已点 | 应用更新」。仅作为一个节点插入 X 标题栏，减少重绘时的相对顺序变化；不新增顶部说明行。
- 「应用更新」始终保留，不再按待更新数量显示/隐藏，也不显示变化的计数。关闭筛选、没有更新、加载或编辑时置灰；有更新时启用。悬停说明它只应用当前已加载通知。
- 主开关负责启用/关闭规则；右侧按钮负责手动应用后续变化，避免阅读时自动收起卡片。功能口径不变。
- 点击应用后立即锁定；保存或应用中不能切换开关，回复框打开时两项都不可操作。设置保存失败仍明确显示「保存失败，重试」，控件宽度保持不变。
- 控件总占位由约 232px 减到 196px，按钮和设置图标位置不随状态切换。保留原有单行标签、回复框固定信息行及原生列表高度，不扩展成新的说明区。
