# 0.12.0 有界自动隐藏点赞通知

## 目的与入口

用户更关注通知中的评论，点赞通知经常占满屏幕；同时不能全部连续折叠，避免 X 为补位不断分页。沿用 0.11.0 的三个固定标题栏按钮，不移动、不新增标题栏控件。

扩展弹窗新增「通知自动隐藏点赞消息」，默认关闭，独立保存到当前 Chrome 的 `autoHideLikeNotifications`。不依赖「隐藏已回且已点」或评论的「自动整理」开启。不开启时维持 0.11.0 的手动单次清理行为。

## 调度与范围

- 开启或主动继续浏览后，空闲 10 秒，仅隐藏视口下方 600px 外的已加载点赞通知，单轮最多 100 条。当前视野和上方不动，按钮不变。
- 每轮消耗一次浏览机会，即使没有安全的卡片也停下。补位、数据更新、普通 DOM 刷新、程序或布局引起的 scroll 事件不能再次授予机会；只有新的真实滚轮、触摸、点击或键盘事件才重新等待。手动整理也消耗该轮机会，不再追加一次自动清理。
- 自动评论与自动点赞共用一个空闲计时器，回复框、后台和离页时暂停，不增加轮询或网络接口。恢复后重新等待 10 秒。
- 复用原生点赞事件图标与稳定通知身份识别。未知结构、缺少稳定时间保留；评论、关注等保留。虚拟节点换成另一通知、切换账号或离页时清除旧标记。
- 自动与手动标记分开恢复。关闭点赞开关只恢复自动隐藏项；手动隐藏项由现有完成项开关恢复。回复框打开时延迟恢复，避免背景跳动。

这只修改已挂载 DOM 的本地显示，不删除 X 通知或真实点赞，不自动发送。一次折叠仍可能让 X 自身加载一批数据，但新到数据不触发后续清理。需要立即清理当前满屏点赞时，使用原有「整理列表」手动执行一次。

## 性能与验证边界

不扫描或渲染本地全部历史，不新增持久化索引或依赖；只扫描当前挂载的通知，单轮结果上限 100。新功能沿用 0.11.0 的满量批量分类优化。

Node 54 项测试通过，覆盖每轮上限、补位不重入、真实用户事件重启、布局 scroll 不重启、独立开关、回复框/后台暂停、手动消耗自动机会、恢复、账号切换及弹窗保存失败回滚。fetch / XHR 的 24 项入口回归通过，误记回复与关闭空框后误隐藏均为 0。

本地浏览器使用真实 10 秒计时，5/5 通过：约 10.26 秒后从 150 条中只隐藏 100 条，再等待 11 秒，余下 50 条和新到消息保持显示；画面内完整可见评论的 top 始终为 63.5px，按钮坐标不变，关注和评论保留，关闭后恢复。见 [验证数据](automatic-likes-0.12.0.json) 与 [截图](automatic-likes-0.12.0.png)。源码、安装包和原安装目录 14 个文件逐字节一致。

0.11.0 已补充真实 Chrome 通知页检查，见 [0.11.0 记录](0.11.0.md)。0.12.0 新开关的时序和连续补位保护使用本地模拟 X 验证；更新后仍需手动重载扩展并刷新真实 X，不能把模拟结果当作真实账号的新功能验收。未代用户发送评论或点赞。
