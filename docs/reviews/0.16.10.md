# 0.16.10 · 个人主页复用回复工具栏

## 范围

从个人主页「帖子」或「回复」页签点击帖子下的小评论按钮，接入现有连续回复会话。复用六组快捷短语及快捷键、AI 推荐、独立点赞、跳过、点赞发送下条、当前作者主页链接。原通知与首页入口保持不变。

- 不新增 X 请求、主动翻页、定时器、持久缓存或列表标签行。
- 使用当前路由与个人主页自身的「帖子／回复」页签链接共同识别入口；回复弹窗暂时切到 `/compose/post` 时仍核对背景主页身份。
- 切换主页、页签或账号结束旧会话；晚到成功回执仍走原本的数据保存流程，不能在其他列表续发。
- 下一条只选择当前已挂载的列表卡片，复用原有已回、自己、隐藏卡片排除与草稿保护。
- 个人主页中转发展示其他人的帖子时，沿用卡片实际帖子 ID 和作者，不将互动记到个人主页主人名下。
- 「媒体／转帖」、帖子详情页及其他未确认入口不新增连续处理支持。

## 验证

- 只读核对已打开的真实 X 个人主页：页签是同一账号的 `/<handle>`、`/<handle>/with_replies` 链接，与入口校验一致。没有点击真实发送、点赞或关注。
- Node 测试 **100/100**，保留前一版未提交的红心保留与性能修复回归。
- Chrome 本地个人主页受控检查 **9/9**：工具栏、输入 100 次不扫描整页卡片、跳过保存完整草稿、实际作者主页、回复只保存一次与按原帖计数、排除自己与已回帖子、回复页签入口、换页签／换人停止旧会话、媒体入口不误启动。
- Chrome 原主页受控回归 **11/11**：为你推荐／正在关注、虚拟节点身份校验、手动红心、普通／长评论入库、切换页签及晚到回执。
- 以上交互和发送回执来自本地模拟，不是实际 X 发送成功证明；AI 复用原实现，本轮没有调用付费模型。

新增代码只在进入个人主页回复时建立少量会话字段，后续核对少数页签链接。未新增全列表观察器，未修改 CSS、筛选器或数据保存结构。本地检查不代表所有 X 界面版本均已实测。
