# 0.16.2 · 四项审阅修复

包含 0.16.1 手动推荐功能，本次修复独立审阅发现的四个问题。没有增加 X 接口、自动分页或重试请求，没有改变通知筛选口径、连续回复发送方式及 AI 默认开关。

## 修复

1. **XHR 复用**：每次 open 清理旧请求监听；load/error/abort/timeout 回调核对当前请求，结束后撤销监听。取消 123 后复用同一 XHR 成功点赞 456，只记录 456。相关旧测试改为 EventTarget，真实模拟多个监听器及 once/remove 行为，避免用单一 handler 覆盖掩盖问题。
2. **部分对象覆盖**：同一响应内同 ID 的帖子也采用非空字段合并；完整与部分对象顺序交换仍保留原帖、父帖与接收者关系。不改变首次提取的字段形状。
3. **重复观察性能**：区分时间刷新与语义字段变化。重复 user/tweet 不重建回复／人物统计或分类索引；只定点刷新已有 root/reply/person 证据时间。关联证据缺失、新账号、新字段、到期和超限仍走完整更新。重复点赞快照继续维护时间顺序，但状态不变不广播。IndexedDB 写入仍使用原增量路径，保存失败后保留待广播状态。
4. **单响应截断**：移除 extract 出口的 500 条截断，保留原 40,000 节点解析预算及原响应大小限制；已解析记录交给现有 500 条合批。成功回复的创建记录在首批即时保存，额外上下文走后续普通批次，创建记录不重复。点赞即时回执也维持小批次，额外上下文保留。

## 回归证据

先运行 `node --test tests/audit-regressions.test.mjs`，最初四项全部失败：旧帖 123 被误记、三项关系被清空、600 只留下 500，以及重复观察触发全量 users 枚举。逐项修复后通过。

新增共 8 项定向检查，覆盖上述四项、关联证据保留时间跨越旧到期点、真实关系补全／新账号、成功回复 600 条上下文分批，以及重复保存不广播／写入失败恢复仍广播。原有测试继续覆盖取消点赞、账号切换、普通／长评论、分页暂停、容量与过期等。

全量 `npm test`：**92/92**。`git diff --check` 通过。

[原始样本](audit-performance-0.16.2.json)。这里包含核心 ingest 与 classify，不含 IndexedDB、Chrome 消息传递、X 网络或实际页面帧率。之前审阅约 30ms 的测量只统计 ingest，不能直接与本表混比。新帖子或真实关系变化仍可能触发全量关联重建；本次优化的是重复观察热路径，不宣称所有操作都是常数时间。
