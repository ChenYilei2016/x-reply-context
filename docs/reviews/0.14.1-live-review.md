# 0.14.1 真实页面复核

## 已确认：标签消失的实际现场

用户提供的原标签页保留现场时，有8条评论、0条标签行、7条聚合通知；控制台反复出现 `Extension context invalidated`，工具栏说明也仍是更新前的版本。说明扩展重载后，这个旧页面的隔离脚本已失去运行时连接；页面内切换主页/通知不会重建该连接。已有标签可能残留，新卡片则无法继续分类。

先保存仓库外截图及匿名指标，确认没有打开的回复编辑器，再完整刷新该标签页：11条评论恢复11条标签，聚合通知为0。随后真实点击「主页 → 通知」，12条评论都有标签，聚合通知仍为0。未修改插件业务代码，未用等待占位掩盖连接失效。

独立检查页向后翻5屏，最终69条已挂载评论都有标签。说明本轮未复现新版运行时有效情况下的永久标签丢失；不等于否认短暂异步等待或其他未捕获结构。

## 回复框与分页

选择完全可见的回复按钮，打开空回复框时 scrollY=0，三个整理控件禁用；确认输入为空后关闭，scrollY仍为0，控件恢复。期间有新评论进入顶部，原评论下移158px，因此这次不能把文档位置变化归为回复框引起，也不能据此保证所有新消息场景都完全不动。

真实自然浏览未遇到整批都被过滤的页。经用户授权，在独立真实X客户端通过开发者工具临时覆盖首批及一条历史响应，保留原生游标，仅留下点赞/关注事件。首批与历史空批均能暂停；但手动继续返回评论后，原生补位又发出下一条历史请求，证明0.14.1尚未满足严格单批继续。此问题已修复为0.14.2，修正版受控实测和边界见 [0.14.2记录](0.14.2.md)。这属于真实客户端受控响应验证，不等同于自然服务端空批。
