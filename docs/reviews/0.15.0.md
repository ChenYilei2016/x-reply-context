# 0.15.0 引用帖支持与整体性能复核

## 范围与结论

复核观察器、记录提取/关系索引、后台串行队列、持久化、批量分类、页面刷新、连续回复、自动整理和网络分页。确认两个实际问题：通知中的他人原帖/引用卡片被标签与完成筛选排除；每次红心修改都全量重算并写回历史，成功回执后还叠加200ms观察合批与250ms页面刷新等待。

## 引用转发

带正文的引用转发按外层作者发布的新原帖显示「别人原帖、文字、红心、我评他、他评我、原帖」。评论依据来自这篇新原帖下的评论（含楼中楼），红心必须点在新原帖本身；内嵌被引用帖及其互动不借给外层，点赞外层的某条楼中楼也不冒充点赞原帖。满足两项后进入原有手动/自动整理，阅读区保护及单轮限制不变。连续回复会考虑尚未回复的这类正文卡片。纯转发聚合事件不是正文引用卡片，不新增全部转发事件过滤开关。

本地完整链路中引用卡片显示全部标签、已完成后可隐藏、关闭筛选可恢复，阅读锚点保持187.445px；见 [链路指标](interaction-performance-0.15.0.json) 和 [虚构页面截图](interaction-performance-0.15.0.png)。

## 存储和数据结构

- 互动记录改为IndexedDB的users/tweets/roots/replies/likes/people六张表，分别沿用原有ID和复合键。外部ID仍是字符串；每类最多10000条、保留90天，账号最多20个。数据口径不变。
- 后台只在启动时读入有界缓存，复用数据库连接及内存快照。后续比较扁平记录，只在一个事务内写入变化项与小元数据；裁剪删除也在同一事务内完成。保存成功才更新持久化快照，失败后可再次保存补齐。
- chrome.storage.local只承担设置、约几十字节的更新通知及迁移时的旧快照。其他标签页不再接收整份历史的新旧值；当前页保存成功后立即刷新标签，其他页合并刷新。
- 初次迁移读取旧replyContext并执行既有裁剪/索引，记录和初始化标记同一事务提交；成功后采用新库，旧快照不删除。该快照是迁移时备份，不包含之后的新增互动，直接降级旧版不会读取新数据。
- 运行时没有双重全量持久化、后台定时刷盘或额外远程请求。跨标签写入仍由一个后台队列串行处理，避免覆盖彼此；小型广播失败不会把已完成的数据库事务误报为保存失败。

## 热路径优化与边界

- 点赞/取消点赞仍等待X明确成功回执，之后立即进入保存链路，不再等200ms合批和250ms页面延时。失败和账号切换不误记，普通时间线数据仍合批，避免大量DOM变化触发连续重绘。
- 纯红心修改只关联变化的红心，不重建全部回复与双方评论统计；只有关系变化、账号变化或过期裁剪时重建。已按时间排序且未过期/超限的集合直接复用，不反复排序、复制。
- CLASSIFY不再计算仅弹窗SUMMARY需要的全量总数。分类仍按100条批次共用关系查找表；不新增可能串账号或沿用撤销红心的长期分类缓存。
- 请求/响应读取有界：点赞Request体最多4KiB，回复Request体最多512KiB，相关响应最多8MiB，提取访问节点与批次数量有上限。解析失败保留X原生行为。
- 列表仅处理当前挂载卡片，标签内容相同不重建，位置预留不随信息晚到伸缩。自动整理沿用空闲10秒、保护当前与上方、一轮后停止；空批后的历史分页仍需逐批确认。此次未改变这些几何和分页规则。
- 冷启动仍需加载有界历史；首次迁移和X网络响应不可视为零耗时。后台新帖子关系更新仍会重算有界索引，未改成复杂的增量关系图。后续若真实测量发现这是主要瓶颈，再针对该路径处理。

## 测量

使用同机相同的满量虚构数据与初始化流程，基线为40c434f的旧核心。数据结构总序列化体积均为8651132字节，避免用数据量不同的结果比较。Node三次样本中位数：

| 项目 | 基线 | 当前 |
| --- | ---: | ---: |
| 100条批量分类 | 6.40ms | 5.31ms |
| 500条红心合并 | 35.59ms | 8.48ms |
| 单条红心合并 | 25.54ms | 7.34ms |

见 [基线](performance-before-0.15.0.json)、[当前](performance-after-0.15.0.json)。这些数字只表示本机计算，不包含X网络、Chrome通信或持久化。

Chrome的真实IndexedDB、本地虚构数据：首次迁移约2151ms，冷读取约205ms，单红心计算约8.6ms、保存约13.5ms。该次只写一条红心及元数据，JSON序列化内容合计396字节，不等同于底层磁盘物理写入量。见 [存储验证](storage-performance-0.15.0.json)。

实际后台/观察器/页面代码接入真实IndexedDB的本地端到端检查：模拟网络153.5ms，成功响应到标签显示78.9ms，总计232.4ms；跨标签更新通知42字节。不是实际X网络或真实账号点赞测量，也不是所有设备的延迟保证。
