# 0.8.2 通知列表位置稳定性审查

## 问题与结论

基准：0.8.1，提交 `f277bfa0022a4905487120ba1021d9c162f1ad0a`。针对开启「隐藏已回且已点」后，快速浏览、关闭未发送回复框、大量通知进入时的跳动。

受控复现确认：打开空回复框期间，读取接口带回一条**已存在的历史回复**，可以让通知从「待确认」变为「已回」。旧版暂停弹窗期间的布局变动，却在关闭后立即隐藏对应卡片。复现中未发送任何 Create 请求，卡片高度从 186px 变为 1px，位置从 312px 变为 497px。这解释了“不发送也消失”的一种可复现机制，不代表已核实用户当时那条通知的全部历史。

没有发现「打开/关闭回复框即保存成新回复」的证据。正文记录仍需要读取到真实回复对象，或收到创建回复接口的成功回执。已存在的历史证据与本次实际发送必须区分。

## 发现与修复

| 问题 | 影响与修复 |
| --- | --- |
| P1：晚到记录导致关闭弹窗即折叠 | 对已显示的通知按账号和帖子 ID 保持本轮布局，后续变化进入「整理更新 N」，用户点击才应用。主动开启筛选也会应用一次。 |
| P1：阅读点上方新通知被二次收起 | 阅读区域及上方新行先保留；仅新出现且位于视口下方 600px 之外的完成项可以直接隐藏。不额外触发滚动、拉取或自动翻页。 |
| P2：旧标签响应覆盖新状态 | 标签查询捕获数据修订号，等待期间记录变化则丢弃过期响应并重新刷新，避免「待确认」假象。 |
| P2：虚拟节点复用残留旧隐藏标记 | DOM 更新时同步清理与当前帖子 ID 不符的标记，已知帖子重绘恢复本轮布局；弹窗暂停期间也先清理身份错配。 |
| P2：只渲染前 100 条标签 | 当前已加载节点分批处理，每批最多 100 条，本机串行分类；超过 100 条也更新标签，无新增网络补抓。 |

布局状态最多保留 10,000 个帖子 ID，退出通知、关闭筛选、切换账号时清理。分类异常保留既有显示状态，避免出错后全量恢复造成跳动。主页隐藏规则、互动计数口径和已移除的「隐藏点赞通知」保持不变。

标签继续使用已有固定高度区域，标签内容、NEW、数字更新不新增一行。新整理按钮位于原标题栏，筛选工作流核对标题高度不变。

## 接口和入口核对

- 读取：TweetDetail、TweetResultByRestId、NotificationsTimeline、HomeTimeline、HomeLatestTimeline、UserRepliesTimeline，REST notifications 的 all / mentions / verified。
- 发送：CreateTweet、CreateNoteTweet；包含 note 文本结构。均经已有统一解析与入库路径。
- 每项分别覆盖 fetch 和 XHR；另有无历史回复的负例，共 24 个受控案例。主页、通知小评论按钮和连续回复最终保存依赖同一响应观察链，未增加点击即记已回的逻辑。
- 连续回复的滚动只由显式「发送并下一条 / 跳过」流程触发，普通关闭回复框没有新增跳转。

## 真实 X 页面验收（2026-10-21）

用户重载扩展后，在受检通知标签再次刷新，确认新的标题栏提示及「整理更新」按钮已加载。其他未刷新的 X 标签不会自动换成新内容脚本，使用前也需要刷新。

- 待确认通知：打开空回复框，确认编辑器为空后关闭。top 保持 107px、height 保持 177px、scrollY 保持 0，仍为待确认且可见。
- 已完成通知：再次打开与关闭空回复框，top 保持 251px、scrollY 保持 861，没有自动消失。
- 连续快速向下滚动再回滚，停止后观察约 10.7 秒：同一阅读点 top 保持 720px，scrollY 保持 2660，隐藏标记与帖子 ID 错配为 0。
- 期间真实新消息进入，上方新卡片保留，已完成通知累计到待整理，原阅读点保持。点击「整理更新」后，当前已加载的已回且已点项收起，未完成项仍可见，待整理按钮消失。
- 仍记录一次首次打开回复框时的整页 127px 位移，所有卡片高度不变；后续两次打开/关闭未再复现。未隔离 X 原生弹窗、焦点滚动与其他扩展影响，因此不把这次有限验收表述为所有位移均已消除。

脱敏数据见 [真实页面验收](notification-live-0.8.2.json)。真实通知截图仅保存在仓库外的本机验收目录，没有纳入开源文件。

本轮没有代用户发送或点赞真实 X 内容。X 自身插入、排序、媒体加载及其他扩展仍可能移动列表，本次修复约束插件引起的二次布局变化。
