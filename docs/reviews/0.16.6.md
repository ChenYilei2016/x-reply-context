# 0.16.6 · 首屏关注数据与有界初始化身份读取

历史说明：本页涉及的双向关注展示及其采集／初始化读取已在 0.16.8 移除。以下保留当时的实现和验证记录。

修复已复现的首屏时序路径：主页请求先于账号链接出现，旧实现因请求账号为空而丢弃关注字段。另从保存的真实 X 脚本确认，全局 `window.__INITIAL_STATE__` 会在初始化后被删除，因此仅读取该全局还不完整。

## 身份边界

- 页面账号已存在时继续使用原页面账号，不扫描初始化脚本。
- 仅首次页面账号尚未出现时，读取明确的 `session.user_id` 及对应用户实体的 ID、用户名，要求两个 ID 一致。全局对象仍在时直接取这几个字段；全局对象已删除时才考虑原脚本文本。
- 初始化身份只用于标记关注请求及页面内存暂存，不改变原互动记录的账号归属规则。页面账号尚未核对前，不发布关注状态。
- 页面账号出现且一致后，按原来的最多 500 条一批补发暂存关系；不一致则清空。切换账号后再切回、导航链接消失或整页离开，不重新借用旧初始化身份。
- 初始化信息缺失、格式不支持、超限或不一致时仍待确认，不把未知响应猜测性地归给后来出现的账号。

## 读取与性能边界

| 项目 | 限制 |
| --- | --- |
| 脚本候选 | 最多前 64 个 script 元素；跳过带 src 及非普通 JavaScript 类型的元素 |
| 前缀读取 | 每个候选最多 256 个 UTF-16 字符；只匹配开头直接赋值 `window.__INITIAL_STATE__ = {…}` |
| 正文读取 | 只接受单一文本节点；先用节点 length 判定，整个脚本最多 256 Ki UTF-16 字符，超限不复制全文 |
| 解析 | 每页最多读取一个候选全文、解析一个 JSON 字面量；失败不重扫，不执行后续 JavaScript |
| 时机 | fetch 在实际请求入口；XHR 到 send 才允许扫描，提前 open 和 READY 不消耗机会 |
| 保留 | 只保留账号 ID、用户名；账号确认或离页后释放初始化结果，无 Cookie、请求头、存储或日志读取写入 |

前缀总读取最多 16 Ki 字符，另加至多 256 Ki 字符的候选正文；这里是字符上限，不是 UTF-8 文件字节上限。原关注 Map 的容量、单批消息上限和过期页面清理不变。

初始化脚本来自页面本身，不请求 HTML、不补查 X。没有新计时器、MutationObserver 或输入热路径扫描；一旦获得身份或完成单次扫描，后续直接返回缓存结果。全局对象存在但内容不完整或冲突时，不改用更旧脚本猜测。

## 验证

- 首屏账号早于／晚于响应两种时序，修复前均丢数据，修复后在页面核对后正常发布。
- 全局已删除但 HTML 原脚本仍在的回归，修复前失败，修复后通过。
- XHR 提前 open、脚本稍后出现、再 send 的回归，修复前失败，修复后通过。
- 输入边界包含：ID 不匹配、账号切换又切回、已核对后链接消失、外链和非 JS 类型、超过 64 个脚本、超大正文、畸形 JSON、字符串内转义与花括号、非 JSON 表达式及尾部代码不执行。
- 全量 Node 测试 **110/110**，差异格式检查通过。新路径不改回复框 DOM/CSS，继续使用原有固定尺寸关注标签。

真实页面存档的离线读取：10 个 script 元素，候选正文 **203,792 字符**；10 次独立初始化平均约 **2.09ms**、最大约 **5.62ms**，随后 1,000 次缓存调用没有增加扫描或正文读取。这里只保留汇总数据，没有保存账号身份或原始初始化脚本。[测量结果](startup-account-performance-0.16.6.json)。这些是本机 Node 离线结果，不代表当前真实 X 的浏览器帧耗时或所有设备性能。

## 交付与限制

源码、README、安装包与原安装目录已同步，现有互动记录和 API 配置保留。重载到 0.16.6，再刷新 X 后生效。本轮没有发送评论、点赞、关注或新增真实 X／模型请求。

本修复覆盖已复现的首屏丢数据路径；尚未取得用户当前截图对应的实时响应证据，不能据此保证所有“待确认”都消失。接口本身缺字段、脚本格式变化或超限仍待确认。真实页面需重载后核对；此记录保留发布前的验证范围。
