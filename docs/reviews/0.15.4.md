# 0.15.4 互动处理与显示性能修复

## 变更

- 接收端合并超过 500 条时分批交付；内容脚本不再丢弃第 11 个观察批次。按 ID 合并重复记录，每批每类最多 500 条，保留部分字段、账号与点赞时间顺序。普通保存失败时保留待处理数据，下一次观察事件再尝试，不自动循环请求。
- 后台仍串行写入，已确认互动与当前分类优先。保留账号初始化依赖，连续处理 8 个优先任务后让普通任务推进；批次间让出事件循环，让互动回执引起的界面读取及时到达。
- 回复框控件和虚拟行纠正合并到下一帧；列表分类仍单独调度。无关侧栏变更不触发列表扫描，后台标签页暂停界面重算。
- 按账号缓存分类索引，红心变化增量更新。记录变更键交给存储层，事务提交成功后才清除；失败后仍能补写。不改变 IndexedDB 格式，不清除现有记录。
- 列表筛选与标签复用同一版本的分类结果，正文摘要与普通标签缓存隔离。同一保存回执和跨标签通知不重复失效；前端缓存最多 1000 项，仅影响界面缓存，不删除历史。
- 已知红心变化不再全量扫描历史；到期、超限或帖子关系变化时仍维护原来的 90 天、每类 10000 条规则。

未改变通知空批暂停、逐批确认、手动发送、手动点赞、连续回复选择、计数口径及阅读区保护；没有新增 X 请求。布局和按钮位置不变。

## 验证

[测量与检查数据](performance-0.15.4.json) 均为虚构数据及本地 Chrome，不代表真实 X 的整体时延。

| 检查 | 结果 |
| --- | --- |
| `npm test` | 71 项通过，包含历史统计、账号/时间顺序、空批暂停及新性能回归 |
| 连续 601 条普通观察记录 | 完整分批保存；重复 ID 合并，已有正文不被空字段覆盖 |
| 接收端 600 条突发记录 | 初始化前后均完整交付，每批不超过 500 条 |
| 最大保留量的热红心与重复分类 | 禁止枚举历史集合的回归通过；仅标记当前红心变更 |
| 24 组接口/入口与 fetch/XHR 回归 | 记录正确，空回复框关闭不隐藏卡片 |
| 浏览器位置回归 | 9/9：包括空框关闭、160 条新增、晚到依据、虚拟行复用、整理与恢复 |
| 浏览器真实 IndexedDB | 6/6：旧记录迁移、增量写入、重开恢复、事务失败重试、晚到原帖关系保存 |

受控排队实验固定每次保存耗时 20ms，8 批后台数据，每批 20 帖：小数据集标签就绪约 **208 → 43ms**；约 6 万条总记录时约 **402 → 54ms**。这是队列模型对照，不是 X 网络耗时。

同一浏览器场景：回复框附加控件约 **286 → 7ms**；原生红心下一帧变化后的插件按钮跟随约 **245 → 10ms**。100 次无关侧栏变动的列表扫描 **100 → 0 次**。关闭空框前后卡片顶部均为 **163.78125px**。

此次容量场景首个点赞新增一条记录，触发上限维护，成功回执至标签约 62ms；后续热更新约 4ms。不要把热路径结果当作首次启动、容量清理或 X 原生界面的承诺。

## 保留的边界

- 冷启动仍按每表上限恢复本地数据；实测约 182ms。首次构建索引、关系变化和到期清理仍有全量计算，本次没有改造为惰性数据库读取或更换数据库结构。
- 尚未取得真实 X 原生红心、原生评论按钮的点击性能时间线；其网络、页面自身和其他扩展影响仍需实际使用确认。
- 本轮没有在真实账号发送、点赞、关注或转发。安装目录文件更新后，需要手动重载扩展并刷新 X，旧标签页不会自动换入新脚本。

复现入口：`npm test`、`node tests/diagnostics/notification-stability-repro.mjs`；`npm run preview` 后打开 `/tests/performance-feedback.html`、`/tests/storage-check.html`，或 `/notifications` 的“空回复框、批量新增与位置稳定”按钮。
