# 0.14.3 旧页面运行时失效时明确停用

## 真实现场与复核

用户报告引用转发排在前面，整理后评论标签不再显示。保留当前通知页读取到：17条帖子、6条旧标签，没有回复编辑器，底部仍显示「发送中」。同一页面控制台持续报 `Extension context invalidated`。新卡片没有分类属性，旧卡片仍残留标签，与运行时断连一致。

经用户明确授权且再次确认没有编辑器后，完整刷新这个标签页。18条帖子中引用转发1条为`not-reply`，其余17条评论都有标签；旧发送浮层消失。再点击「整理列表」，17条评论仍有标签，缺失数0。引用转发本身不显示评论互动栏属于现有分类规则；没有复现其阻断整批渲染。不能以此否认其他未捕获卡片结构，但本次失效有直接日志证据。

## 最小修复

- 在刷新调度、消息收发、连续回复入口检查扩展运行时；明确收到失效错误也进入同一停用分支。
- 结束旧连续会话并清理其计时器、工具栏和「发送中」浮层。迟到的回复结果不会再驱动自动下一条。
- 暂停整理和标签刷新，保留已经显示的行高及折叠状态，不为失效恢复整批隐藏项，不追加占位。
- 只显示一个固定底部提示，由用户点击刷新。不自动刷新、不重试发送；存在回复框/附件时先提示保存草稿。

运行时失效的旧隔离脚本不能凭站内切换恢复连接，完整刷新仍是恢复手段；此次改动避免后续失效继续以旧按钮和旧发送状态误导用户。新代码无法追补已经失效的旧脚本，安装后仍需重载扩展并刷新X一次。
