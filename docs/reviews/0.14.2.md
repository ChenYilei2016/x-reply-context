# 0.14.2 空批后保持逐批确认

## 发现与修正

在用户授权的独立真实 X 检查页，用 Chrome DevTools Local Overrides 临时覆盖首批和一条历史响应，保留真实包装、事件字段及游标。0.14.1能过滤并暂停空批，但点击一次继续后，只要返回评论就解除整个暂停，X的原生补位又发出第二批。没有待发请求时点击继续也会解除暂停。针对这两个入口的回归测试在旧实现均失败（实际请求3次，预期2次）。

0.14.2让空批进入本次浏览的逐批确认状态。一次点击只放行一条等待请求，或为下一条原生历史请求预留一次机会；评论返回后仍暂停后续补位。顶部增量不消费机会，也不解除历史暂停。离开通知/回复流程、切换账号或调整过滤开关会重置状态。保留原有等待队列及游标集合上限，不新增主动请求、轮询、存储字段或接口。浮层区分「本批没有可显示通知」和「本批已加载」，仍固定于底部，不插入列表占位。

## 验证与边界

- 全部53项Node检查通过；XHR和fetch两个入口均覆盖，先失败再修复。
- 本地虚构客户端模拟空页重试及有评论后的补位：请求2次停下，点击一次为3次，额外补位仍被拦截；1020条点赞/关注不渲染，3条评论保留，阅读锚点146.5px保持不变。见 [匿名指标](network-filter-0.14.2.json) 和 [本地截图](network-filter-0.14.2.png)。
- 用户重载0.14.2后，真实X客户端的受控历史空批进入暂停。网络面板筛选历史Bottom请求：共2条，分别为受控空批和手动继续；再次触底、等待、上滚及开关空回复框后仍为2条。Top增量继续接收。该结论来自受控响应，不冒充自然服务端空批。
- 无发送的回复框复核：0.14.1一轮开关前/中/后scrollY均2771.5，评论top均222px。0.14.2复核关闭前后scrollY均4168、评论top均222px；但打开时从4209.5调整到4168（约42px），本轮未隔离X自身定位与实时插入的全部因素，不宣称所有开框和新消息场景零位移，未加入强制滚动补偿。
- 空批等待不追加事件占位，等待期间列表高度未持续增长。触及底部可能看到X原生等待指示和暂停浮层；这是停下等待用户的状态，不额外补页填满屏幕。真实已完成评论折叠测得每条约0.0078px，不能把原生虚拟列表的上方高度缓存全部归于插件。
- 之前标签永久缺失的实际现场是扩展重载后的旧页运行时失效，完整刷新恢复；站内「主页→通知」不会重新注入旧页脚本，README升级说明已明确。见 [原现场复核](0.14.1-live-review.md)。

源码、安装包及原安装目录14个文件逐字节一致。临时覆盖已关闭，网络缓存选项已恢复，独立检查页已关闭。未发送评论、点赞、关注，也未自动操作其他账号功能。真实账号截图及原始响应仅存仓库外；公开证据只含虚构账号。
