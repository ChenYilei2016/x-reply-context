# 0.15.8 快捷填入重复修复

## 原因与修复

真实页面只存在一套快捷按钮，但同一句出现在 Draft 管理的 `data-text` 节点内、外，呈现两遍。0.15.7 使用浏览器原生 `insertText` 修改编辑 DOM，与受控编辑器同步内容存在冲突。此前普通 contenteditable 测试不足以验证 Draft 的编辑状态。

- Draft 编辑器改为通过其 `paste` 事件处理入口更新内容，等待一帧让选区同步；不再直接执行原生 DOM 插入。
- 编辑器未接收粘贴时提示手动输入，不追加原生插入或自动重试，避免双写。
- 填入期间防重入，并暂缓插件的发送与跳过；等待期间换对象、关闭编辑器、草稿变化、选区不再折叠或输入法组字时取消填入。
- 普通 contenteditable 保留原生编辑路径；不改变现有随机词句、末尾标点或手动发送规则。不使用系统剪贴板、不增加权限或 X 接口请求。
- 不自动去重、清空或改写已经输入的真实草稿。

## 验证与边界

- 74 项 Node 检查通过。
- 使用独立安装的 React 17.0.2 / Draft.js 0.11.7 做本地受控编辑器测试，不是普通 contenteditable 模拟。
- 修复前，空 Draft 编辑器发生 React 节点移除异常，内部文本已有内容但 DOM 编辑器丢失；与真实页面的重复 DOM 一同证明旧编辑路径不兼容，未将本地异常冒充同一版本 X 的完整复现。
- 修复后空框、已有草稿、选中原稿、编辑器拒绝接收、同帧连点 5/5 通过；DOM 文本与 Draft 状态一致，原生插入次数及发送次数均为 0。[结构化证据](quick-replies-0.15.8.json)
- 真实 X 页面本轮仅只读检查；没有继续填字、发送或点赞。重载 0.15.8 后仍需用户确认真实编辑器兼容性。

受控测试依赖只用于开发验证，不打入扩展，也不新增生产依赖。复现方法：在独立临时目录安装 `react@17.0.2 react-dom@17.0.2 draft-js@0.11.7 immutable@3.8.2`，运行 `node tests/diagnostics/draft-editor-server.mjs /absolute/test-dependencies/node_modules`，打开返回地址，选择场景并点击检查。
