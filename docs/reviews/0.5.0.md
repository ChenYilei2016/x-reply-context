# 0.5.0：主页连续评论

在“主页 → 为你推荐”的帖子卡片点击原生小评论按钮，即可使用“发送并下一条”和“跳过”。后续候选取当前已挂载的卡片，不要求位于当前卡片下方，不主动翻页。

## 行为与保存口径

- 主页原帖候选略过自己的原帖、已经评论过的原帖（含楼中楼）、本轮已处理的卡片。只点红心不排除。手动打开的第一条仍由用户决定是否再次回复。
- 通知继续按“账号 + 原帖 + 对方”判断已回，不把同帖其他人误标为已回。主页原帖的跳过依据允许使用该原帖下任一自己的评论；这不改变通知与双方计数的口径。
- “我评他 / 他评我”仍按评论对方的不同原帖数统计，同帖多次只计 1。
- “正在关注”和自定义主页页签不启动连续处理；这些页面的原生回复仍记录。切换来源页签、离开页面或切换账号结束本轮。
- 每次只有用户点击才发送。请求、账号、回复目标和成功回执匹配，且统一保存流程完成后，才筛选下一条。原生发送也使用这条保存路径，不会因为没有点击自定义按钮而漏记。
- 发送失败或结果不明停下；有草稿的跳过沿用原生关闭与保存流程。新消息不打断当前编辑，下一步时已挂载的卡片可以参与候选。
- 主页不注入逐条标签或占位高度。通知固定行高、弹窗打开时保留标签的行为不变。

## 接口与入口覆盖

| 环节 | 本次检查范围 |
| --- | --- |
| 主页帖子读取 | `HomeTimeline`、`HomeLatestTimeline` |
| 发送回执 | `CreateTweet → create_tweet`、`CreateNoteTweet → notetweet_create` |
| 请求方式 | `fetch(url, init)`、`fetch(Request)` 克隆读取、`XMLHttpRequest` |
| 结果结构 | 普通结果、`TweetWithVisibilityResults` 包装、`note_tweet` 长正文 |
| 操作入口 | 主页小评论按钮、通知评论、详情评论、X 原生发送、自定义发送并下一条 |
| 后续判断 | 成功记录保存一次，后续通知显示已回，原帖数按原口径更新 |

继续只观察页面已有的同源白名单接口，不新增权限、外部服务或主动请求。没有完整成功依据时，不自动进入下一条。接口字段参考 [Twikit 的 GraphQL 实现](https://github.com/d60/twikit/blob/main/twikit/client/gql.py)及[返回结果解析](https://github.com/d60/twikit/blob/main/twikit/client/client.py)，实际覆盖由本项目测试与页面检查确认。

## 验证结果

- `npm test`：37 项通过（包括 8 种主页接口 × 评论接口 × 传输组合）。模拟 `/home`、`/compose/post`、帖子详情与通知路由，不依赖发送时的页面路径。
- 本地浏览器完整链路：主页长评论 → 只保存一次 → 自动打开下一篇未评原帖 → 返回通知显示“文字-已回、我评他 1”。见 [链路证据](../home-flow-0.5.0.json)及[通知截图](../home-notification-0.5.0.jpg)。背景主页卡片高度前后一致，且没有逐条标签。
- “正在关注”用原生回复：不显示连续工具栏，成功仍只保存一次，不自动打开下一条。见 [原生入口证据](../home-native-0.5.0.json)。
- 主页失败：不进入下一条、不记成功；随后跳过，原生模拟草稿保存一次并打开下一篇。见 [失败与草稿证据](../home-failure-0.5.0.json)。
- 通知回归：9/9 弹窗布局、5/5 新消息行高通过，测量偏移为 0。见 [布局结果](../layout-home-release-0.5.0.json)。
- 安装包逐文件与源码比对一致；沿用原 Chrome 扩展目录和 ID，管理页显示 0.5.0 已重新载入。见 [版本截图](../extension-loaded-0.5.0.jpg)。
- 真实 X“为你推荐”：原生小按钮打开回复框，显示主页工具栏；点击空内容“跳过”打开下一条，已处理数变为 1。见 [页面证据](../home-live-0.5.0.json)及[界面截图](../home-reply-live-0.5.0.jpg)。检查完关闭空回复框。

真实页面仅验证入口、布局和跳过，没有替用户发布评论或点赞。真实实发与原生草稿保存仍需正常使用确认；本地模拟成功不等于真实发送成功。截图中灰色建议文字来自 XReply，编辑器实际为空，未接受或发送该建议。
