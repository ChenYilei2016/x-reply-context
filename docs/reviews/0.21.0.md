# 0.21.0：互动统计与缓存分离

## 变化与边界

旧版人物次数会随帖子/原帖缓存淘汰而重算下降。新版以 `interactionFacts` 保存账号、对方、方向、原帖组成的唯一事实，`people` 保存人物汇总。事实与计数同事务提交；普通缓存仍有90天期限，每类上限改为20,000。独立事实和人物各限20,000，不自动淘汰，容量不足会标记不完整。

统计仅依据本浏览器已确认数据，不增加X接口请求。旧汇总缺少去重明细时保留为历史下限，与已确认数取较大值，不能直接相加；因此低于旧下限的新确认不一定立即改变显示下限。历史缺口显示 `≥N` 或“待确认”，不推断NEW。原帖内的文字/红心依据仍使用既有索引，与人物累计口径分开。

## 备份与失败恢复

1. IndexedDB 从版本1升级到2时，在版本变更事务中逐条复制旧六类记录及元数据到 `backups`，备份失败整个升级回滚。
2. 可用的旧 `chrome.storage.local.replyContext` 快照也先备份；原快照不删除，AI配置不纳入备份。
3. 迁移从现存记录和旧快照提取可确认事实，事务提交后才采用新版汇总。迁移中断保留旧表及备份，重试不重复计数。
4. 运行时按最多500条事实一批提交事实与计数；全部事实批次成功后再保存正文缓存，避免进程中断后将未记账的正文当成已处理。失败队列有上限，无法保存的事实会标记不完整，不静默丢失并声称完整。
5. 升级前备份可通过扩展弹窗导出JSON，不上传服务器。数据库升级后旧版扩展不能直接读取，勿直接降级。

## 性能边界

事实表不执行全量 `getAll`；冷启动核对条数并加载有界缓存/人物汇总，事实按批内唯一键读取。重复观察依靠当前缓存的事实签名避免重复入库；人物累计不再全量清零重算。现有帖子/原帖索引维护仍按原有有界流程处理，未宣称所有处理均为常数时间。

本机虚构数据、真实浏览器IndexedDB测量：

- 各缓存满20,000条的旧local快照首次迁移约4.2秒，仅执行一次。
- 单次红心计算约2.2ms，保存约8.4ms；仅两次put：一条红心及小元数据。
- 满量冷读取约363ms；较小事实集、20,000条帖子缓存的冷读取约99ms。
- 已建立分类索引后的100条分类约0.1ms。

这些是本地样本，不是实际X请求耗时或所有设备保证。真实用户库已由用户回传页面状态确认迁移完成、升级前备份保留；未直接读取浏览器内的实际数据库。

## 验证

- 14项真实IndexedDB本地检查：备份失败回滚、迁移失败回滚、旧快照保护、去重、事务中断重试、缓存淘汰不减数、冷启动不全量读事实、90天过期不减数、2万容量保护等。
- 9项满量存储回归：单红心增量写入、事务失败恢复、帖子晚到、真实点赞/取消证据优先、旧响应时间保护。
- 回复框历史不完整显示为“我评他 待确认／他评我 ≥1”，不显示NEW；切换前后回复框高度536.5px、滚动位置78px均未变化。
- 检查只操作localhost虚构数据，未调用真实模型，未在X发送、点赞或补抓历史。
