# 创作工作台 v2 设计稿

日期：2026-11-16 · 状态：**已确认**，按第 14 节任务实施· 对照基线：`4261dde`（0.26.0 工作台）

## 1. 目标与定位

- 账号方向：从“娱乐搞怪转发”转向 **小娱乐、大 AI 科技**；主力形态是 **中短帖观点**；账号有 Premium。
- 工作台要省掉的人工：**找选题（最耗时）→ 判断值不值得写 → 想角度 → 成稿**。发布始终由人点击确认。
- 对标：**复刻并超越 BlueV**（见第 13 节）。
- 衡量标准：打开工作台 10 分钟内能挑出 2～3 个值得写的选题，并得到可直接微调发布的稿子。

## 2. 对 0.26.0 的评审结论

| 问题 | 结论 |
| --- | --- |
| 素材只有三路 RSS，按时间排序，没有热度信号 | 选题仍靠人工逐条判断，核心痛点未解决 → **推翻**，改为多渠道 + 热度信号 |
| 扩展已拦截 X GraphQL 响应，却没利用其中的浏览量、互动、粉丝数 | 最有价值的零成本数据未用 → **新增 X 浏览采集** |
| 产出只有“约 N 字一篇”，800 字档与 X 形态无关 | → 按 **X 内容形态** 组织，并显示首屏截断位置 |
| 一次只出一稿；角度是一段纯文本，只能整段带入 | → **结构化角度**，一键按某个角度出 **3 个候选** |
| 风格硬编码 4 种，人设写死在代码里 | → 人设可编辑 + **我的爆款样本**自动作参考 |
| 复制 → 打开 compose → 粘贴；“已用”≠“已发”，没有数据回收 | → 预填发布 + 自动关联已发帖 + 复盘 |
| 同一事件多张卡片 | → **话题聚合** |
| `creation.js`、`creation.css` 是压缩风格，单文件堆叠全部职责 | → 按职责拆模块，恢复可读的代码风格 |

保留并复用：AI 请求通道（`AI_REQUEST` 排队、取消、超时）、`ai-config.js` 的多组 API 配置、RSS 拉取的安全限制（域名白名单、2 MB 上限、15 秒超时）、“只用素材支持的事实、区分摘要与正文”的提示词约束。

## 3. 总体流程

```
渠道（X 浏览采集 / 你的 bot / 热榜 / RSS）
   → 统一素材结构 → IndexedDB
   → 选题雷达（分类、话题聚合、热度排序）
   → 角度（结构化，可单选）
   → 成稿（形态 + 人设 + 样本，3 个候选）
   → 编辑（加权字数、首屏标线）
   → 发布（预填 X，人工点发）→ 自动关联已发帖 → 复盘数据
```

## 4. 统一素材结构

### 4.1 字段

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定标识。X 帖子用 `x:<帖子ID>`，其他用规范化后的 URL |
| `channelId` | 来源渠道，如 `x-observed`、`bot-feed`、`baidu-hot`、`ithome` |
| `kind` | `x_post`（X 帖子）／`article`（文章新闻）／`hot_topic`（热榜条目） |
| `category` | 分类枚举：热点、AI、科技、产品、开源、X 情报 |
| `title`、`text` | 标题与正文；`coverage` 标明完整度：仅标题／摘要／正文 |
| `url` | 原文链接（仅 HTTPS） |
| `author` | 作者账号、名称、粉丝数（有则填） |
| `publishedAt`、`firstSeenAt`、`lastSeenAt` | 发布时间、首次采集、最近采集 |
| `metrics` | 浏览、点赞、转发、评论、引用、收藏，或热榜名次 |
| `metricsSource` | 指标可信度：`x_observed`（扩展从 X 实测）／`channel_reported`（渠道报告，例如 Grok 汇报）／`rank_only`（只有名次） |
| `snapshots` | 指标快照，每条最多保留 8 个，用来判断是否在加速 |
| `media` | 图片、视频的类型和地址（只作参考，不自动转载） |
| `note` | 渠道附带的说明，例如 bot 写的“为什么值得写” |
| `topicKey` | 话题聚合键 |

### 4.2 派生指标（只对有真实数据的条目计算，不虚构）

- **流速**：浏览量 ÷ 发布至今的小时数。和 BlueV 的口径一致，是平均值，不是瞬时速度。
- **爆文倍数**：浏览量 ÷ 作者粉丝数，用来发现小号的爆帖。
- **加速度**：最近两次快照之间每小时新增的浏览量。至少要有两次快照才显示。
- 热榜条目只显示名次和上榜时长，不和 X 指标混在一起排序。

### 4.3 分类与渠道规则用枚举封装

`MaterialCategory`、`MaterialKind`、`MetricsSource` 各自带判断方法，例如“是否参与流速排序”“展示标签”，避免 `if` 判断散落在 UI 里。

## 5. 渠道

### 5.1 适配器接口

```
拉取型：{ id, name, category, intervalMinutes, hosts, fetch(signal) → 原始数据, normalize(原始数据) → 素材[] }
推送型：X 浏览采集，由页面拦截批量写入，不需要调度
```

- 调度：后台用 `chrome.alarms` 在浏览器开着时按渠道周期拉取。全局并发 2，失败按 15 → 30 → 60 分钟退避，渠道状态（最近成功时间、错误）可在界面查看。
- 只读公开数据，单个渠道最短周期 30 分钟，并加内容大小和超时上限。

### 5.2 首批渠道（2026-11-16 已从本机实测）

| 分类 | 渠道 | 方式 | 实测 |
| --- | --- | --- | --- |
| X 情报 | X 浏览采集 | 页面拦截，零额外请求 | 现有拦截代码已经能拿到字段 |
| X 情报 | 你的 bot（Grok / Codex） | 本地 feed 文件，见第 6 节 | 待你和 bot 约定 |
| 热点 | 百度热搜（实时榜） | 公开 JSON | ✅ 200 |
| 热点 / 娱乐 | B站热门 | 公开 JSON | ✅ 200 |
| AI | OpenAI News、Google AI、量子位 | RSS | ✅ |
| 科技 | IT之家 | RSS | ✅ |
| 产品 | Product Hunt | Atom | ✅ |
| 开源 / AI | Hacker News 首页、GitHub Trending | RSS／解析网页 | ✅ |

暂不接：微博热搜（403）、知乎热榜（401）、抖音热榜（需要签名）、机器之心（跳转付费）、36氪（不是 RSS）。这些需要登录，可以交给 bot 在本机抓取后写进 feed。

### 5.3 X 浏览采集

- 在现有 MAIN world 拦截（`core.js` / `observe.js`）里，从帖子节点额外提取：`views.count`、`legacy.favorite_count / retweet_count / reply_count / quote_count / bookmark_count / created_at`，以及作者粉丝数。
- 每 5 秒合并成一批（单批最多 200 条）发给后台写库，避免逐条通信。同一帖子再次出现时追加快照（间隔至少 30 分钟）。
- 保留策略：7 天或 2 万条，先到先触发。48 小时后浏览量仍低于阈值的条目先清理。
- 不发任何额外的 X 请求，不翻页，不自动打开页面。

## 6. 与 bot 对接（云端运行，开机同步到本机）

bot 的代码改不了，但可以让它按约定的格式输出文件（约定见附录 A）。

**文件约定**：bot 维护一个滚动文件 `feed.json`，保留最近 200 条。每次写入时先写 `feed.json.tmp`，再改名覆盖，避免扩展读到写了一半的文件。

```json
{
  "schema": "xrc.feed/v1",
  "channel": { "id": "grok-bot", "name": "Grok 机器人" },
  "generatedAt": "2026-11-16T12:00:00+08:00",
  "items": [
    {
      "id": "x:1890000000000000000",
      "kind": "x_post",
      "url": "https://x.com/someone/status/1890000000000000000",
      "text": "帖子原文",
      "coverage": "full",
      "lang": "zh",
      "publishedAt": "2026-11-16T09:30:00+08:00",
      "author": { "handle": "someone", "name": "某人", "followers": 12000 },
      "metrics": { "views": 250000, "likes": 3200, "reposts": 410, "replies": 180, "observedAt": "2026-11-16T11:58:00+08:00" },
      "tags": ["AI"],
      "note": "一句话说明为什么值得写"
    }
  ]
}
```

**读取方式（已确定：本机静态服务）**

- bot 在云端 24 小时运行；Mac 开机时把结果同步到本机目录。
- 本机用 launchd 常驻一个只读静态服务：`python3 -m http.server 8765 --bind 127.0.0.1`，服务目录就是同步目录。
- 扩展后台按周期请求 `http://127.0.0.1:8765/feed.json`。manifest 已声明 `http://127.0.0.1/*` 可选权限，首次在工作台授权即可。
- Mac 刚开机时 bot 会一次补同步一大批，所以 `feed.json` 至少保留最近 48 小时或 500 条，扩展按 `id` 去重合并，不会漏也不会重复。
- 服务不可用（没开机、没同步）时渠道显示“离线”，其他渠道照常工作。

bot 返回的指标标记为 `channel_reported`。等你在 X 上刷到同一条帖子、扩展采到真实数据后，自动升级为 `x_observed`。Grok 搜索 X 的费用和预算都在 bot 那边控制，扩展里不存 xAI Key。

## 7. 选题雷达（界面）

- 顶部分类标签：全部 · 热点 · AI · 科技 · 产品 · 开源 · X 情报，每个标签显示数量。
- **话题聚合**：同一事件按标题归一化和关键词重合（48 小时窗口）合并成一张话题卡，显示“N 个来源”和最高的 X 浏览量。需要更准的合并时，可以按需调用 AI 归并，不对整个库批量调用。
- 排序：X 帖子按流速、爆文倍数或加速度；热榜按名次；文章按新鲜度加 AI 关键词相关度。
- 点开话题卡出详情抽屉：相关 X 帖子（附指标）、相关新闻、原文链接、一键“找角度”。
- 卡片操作：收藏、隐藏、选入（最多 3 条）。已经用过的话题会打标记。

## 8. 角度与成稿

### 8.1 结构化角度

模型按 JSON 返回 3～5 个角度，每个包含：

- 类型枚举：解读、反常识、清单、教程、吐槽、预测、对比、故事
- 钩子句、提纲、依据（对应哪几条素材）、风险提示（比如事实不足、时效已过）

每个角度卡片都可以单独点“用这个写”。

### 8.2 成稿

- **形态枚举**：中短帖观点（默认，约 150～400 字）、引用转发（约 50～150 字，附原帖链接）、线程（后期）、长帖（后期）。
- 一次出 **3 个候选**，开头钩子各不相同。用户挑一个进编辑区，其余候选保留，可以随时切换。
- **人设**：可编辑，默认按“小娱乐、大 AI 科技”撰写；不在代码里写死个人信息。
- **我的爆款样本**：从扩展采到的你自己的帖子里，按浏览量挑最近 60 天的前 5 条作为风格参考，也可以手动置顶或排除。
- **每个步骤单独选模型**：在 AI 设置里新增“创作：角度模型／成稿模型”，从现有 1～10 组 API 配置中选择，不影响评论功能。

### 8.3 编辑区

- 按 X 规则计算加权字数（中文、日文、韩文每字计 2），显示 Premium 上限。
- **首屏标线**：时间线上超过约 280 加权字符就会折叠成“显示更多”，钩子必须放在标线之前。
- 有事实依据的地方可以回看来源原文，素材抽屉一直可以打开。

## 9. 发布与复盘

- 用 `https://x.com/intent/post?text=…` 预填正文；引用转发时附上原帖链接。仍由你在 X 页面点击发布。正文太长导致链接超长时，退回到复制粘贴。
- **自动关联**：现有拦截能看到 `CreateTweet` / `CreateNoteTweet` 的响应，正文与草稿一致时，草稿标记为“已发”并记下帖子 ID。
- **复盘**：你之后浏览到自己的帖子时顺带更新数据。草稿库显示每条已发帖子的浏览、点赞，以及 24 小时快照，并按角度类型和形态统计平均表现。

保持项目现有约定（无构建、`globalThis.XReply*` 命名空间、IIFE），新代码放进 `extension/creation/` 子目录：

## 12. 合规边界

- 不自动发帖，不额外请求 X，不自动翻页；X 数据只来自你正常浏览时页面已经加载的内容。
- 第三方站点只读取公开数据，控制频率；素材保留出处，不原样搬运他人的独创表达，图片和视频不自动转载。

## 13. 对标 BlueV：复刻与超越

| BlueV 能力 | 我们的做法 | 结论 |
| --- | --- | --- |
| 爆文雷达：监控优质账号，按流速排序 | X 浏览采集 + bot（Grok 搜 X）+ 多次快照 | **超越**：除平均流速外还有加速度和爆文倍数，内容来自你自己的圈子 |
| 话题：跨平台合并，显示“N 个平台同时在热” | 话题聚合 + 来源数 + 相关 X 帖子 | 复刻 |
| 角度生成：已写过的角度（蓝点）／新角度（绿点），潜力分 1～10 | 角度对照已采集的同话题 X 帖子：已有人写的附参考帖和浏览量，新角度单独标出；潜力只根据相似帖的真实表现给出，没有依据时显示“无依据”，不编分数 | 复刻，口径更可信 |
| AI 改写：风格 + 字数，多链接融合 | 形态 + 人设 + 爆款样本，3 个候选 + 首屏标线 | **超越** |
| 流速勋章（插件在 x.com 帖子上显示） | 时间线卡片上显示流速／爆文倍数小标签，一键加入素材 | 复刻 |
| 蓝V海报（引用原帖生成图片） | 浏览器内用 Canvas 生成引用卡片图，原文不改动 | 复刻（排在后面） |
| 视频下载 | 已有（`post-video.js`） | 已具备 |
| 定时发布（OAuth 授权） | 不接 OAuth；预填后可用 X 原生的定时发送 | 不复刻，不增加账号风险 |
| 账号分析（粉丝每日变化） | 浏览自己主页时记录粉丝数，复盘页显示趋势 | 复刻（排在后面） |
| —— | 发布后自动关联 + 数据复盘 + 爆款样本反哺 | **BlueV 没有的闭环** |
| —— | 通用渠道协议：任何 agent 或服务按 `xrc.feed/v1` 输出即可接入 | **BlueV 没有** |

## 附录 A：给 bot 的输出约定

> 请把以下内容原样转给你的 bot。

1. 每次运行后，把结果写进同步目录下的 `feed.json`。先写 `feed.json.tmp`，写完再改名覆盖。
2. 文件格式见第 6 节示例。`schema` 固定为 `xrc.feed/v1`。
3. `items` 至少保留最近 48 小时或 500 条，新的在前。同一条内容的 `id` 必须稳定：X 帖子用 `x:<帖子ID>`，其他内容用原文链接。
4. `kind` 取 `x_post`、`article`、`hot_topic` 之一；`coverage` 取 `title`、`excerpt`、`full` 之一。
5. 指标只填真实读到的数字，读不到就不填，不要估算；`metrics.observedAt` 填读到数字的时间。
6. `tags` 可以用：`AI`、`科技`、`产品`、`开源`、`热点`、`娱乐`。
7. `note` 用一句中文说明为什么值得写，不超过 80 字。
